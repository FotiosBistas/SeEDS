Detailed Description

Owns and runs multiple ServiceBase-derived services in parallel threads.

Note
Logging is initialized with both a colored console sink and a file sink. The daemon does not own OS process lifetime; callers should create a main loop (e.g., wait on a signal) and invoke stop() for a graceful shutdown.

◆ start()

void SNDSDaemon::start ( )
inline

Start all registered services concurrently.

Spawns one thread per service and invokes init() on each. Since service loops are typically blocking (reactors), this method returns immediately after threads are created.

Warning
Ensure services were added via addService() before calling. Subsequent calls without stopping first may create duplicate threads for the same services.

◆ stop()

void SNDSDaemon::stop ( )
inline

Stop all services and join their threads.

Calls stop() on each registered service (cooperative shutdown), then shuts down all shared queues exposed by ServiceBase, and finally joins every service thread.

Postcondition
No service threads remain joinable.
