Detailed Description

Central coordinator and state machine for SNDS intra-messages.

Responsibilities:

  • Subscription management: first-subscriber triggers interest to subscribe a remote scope, deduplicating subsequent subscriptions for the same name.
  • Lookup lifecycle:
    • GET_BY_ID: deduplicate concurrent requests for the same ID; clear state on first reply.
    • GET_BY_TYPE: fetch registry file → fan out getByIDForType for each ID listed → aggregate results.
  • Temporal query lifecycle:
    • Track pending queries keyed by a stable hash, buffer partial results, detect the final chunk, apply optional field filters, and emit a single normalized JSON bundle.

◆ init()

void Worker::init ( )
overridevirtual

Main service loop.

Reads intra-messages from ServiceBase::v_to_worker and dispatches to sender-specific handlers:

  • HTTP_SRV → @_handle_http_server_intra_message
  • CONSUMER → @_handle_consumer_intra_message
  • PRODUCER → @_handle_producer_intra_message

The loop exits when ServiceBase::running becomes false or the queue is shut down.

Reimplemented from ServiceBase.

Handle temporal query responses (direct or aggregated).

Parameters
parent_query_hashHash used to locate pending state (ignored in direct mode).
contentRaw JSON (may contain leading/trailing noise; utils extract slices).
last_interesttrue if this is the final chunk for the parent query.
is_direct_modetrue if the payload is already the target document.
  • Direct mode: extract one item, optionally clear GET_BY_* pending sets for that item, wrap as {"mode":"direct","items":[...]} -> HTTP.
  • Aggregated: split into slices, sanitize/parse, apply field filters (if present), buffer under parent_query_hash, and on last_interest build a manifest bundle then send to HTTP. State is erased afterwards.
