Detailed Description

HTTP ingress/egress service built on cpp-httplib.

The SNDSHTTPService adapts HTTP requests into internal SNDS intra-messages and returns replies back over HTTP. It is responsible for:

  • Parsing query/body parameters via the QUERY_PARAM_LIST macros.
  • Classifying requests into snds_intra_message::SNDS_INTRA_MESSAGE_TYPE (e.g., GET_BY_ID_REQUEST, TEMPORAL_QUERY_ADVERTISEMENT) based on the HTTP verb and which parameters are present.
  • Pushing outbound messages onto the appropriate service queue.
  • Waiting for a single response message and using its payload as the HTTP response body.

Endpoints

  • GET /
    Reads URL query parameters, maps them to intra-message parameters, infers a GET classification, and forwards to the Worker queue (ServiceBase::v_to_worker).
  • POST /
    Reads the request body (treated as query-string tokens or JSON upstream), maps parameters, infers a POST classification, and forwards to the Digital-Twin queue (ServiceBase::v_to_dt).

Message flow (high-level)

*     HTTP client  -->  SNDSHTTPService (GET/POST)  -->  intra-message (typed)
*                                                -->  target queue (Worker/DT)
*                                                <--  response message (payload)
*     HTTP client  <--  200 + payload (sanitized)
*

Concurrency

  • The embedded cpp-httplib server runs in its own thread created inside init().
  • The main thread polls ServiceBase::running to coordinate shutdown, then stops the server and joins the thread.

Response payload handling

The service trims any leading non-JSON noise from the response payload by dropping bytes until it sees ‘’{'or'['` (best-effort; upstream components should emit clean JSON).

Note
This service is an adapter; it does not interpret domain semantics beyond parameter extraction and message-type inference. The Worker/DT (and downstream components) produce the actual results.
