Static queues used by all services to exchange intra-messages.

The daemon wires services together by writing/reading from these queues:

  • v_to_proxy, v_to_dt, v_to_producer, v_to_consumer, v_to_worker, v_to_service (naming reflects the intended receiver).
Note
This approach is intentionally simple for a single-process prototype. If you need multi-process or distributed operation, plug in a real broker.

Detailed Description

Base class implementing shared infrastructure for SNDS services.

Responsibilities:

  • Configure logging to both console and file, tagged by service name.
  • Initialize NDN Face, KeyChain, and a schema-based Validator.
  • Expose overridable handlers for Interest/Data/Nack/Timeout.
  • Provide a uniform lifecycle (init() loop + stop()).
  • Offer a convenience method to sign and send Data packets.

Threading model:

  • Each derived service typically runs its own init() loop on a thread controlled by the daemon. The shared queues supply back-pressure and handoffs between services.

Construct and configure a service with logging and SNDS/NDN parameters.

Parameters are taken by value and moved internally, so both lvalues and rvalues are accepted. The constructor also attempts to load an NDN trust schema from ./trust-schema.conf.

virtual void ServiceBase::stop ( )
inlinevirtual

Stop the service gracefully.

Sets the running flag to false, shuts down the NDN Face, and flushes the logger. Derived classes may override if they need additional cleanup, but should call ServiceBase::stop().
